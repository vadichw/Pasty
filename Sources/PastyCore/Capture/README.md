# Capture

Purpose: notices new things to remember — whatever is copied to the clipboard, and new screenshots and screen recordings saved to disk — classifies them and hands them to Storage.
Depends on: Settings, Storage

Flow: `ClipboardMonitor.check()` (every 0.5 s) or `ScreenshotWatcher` → `ClipboardMonitor.record(...)` → `HistoryStore.add(...)`.

## ClipboardMonitor

Purpose: polls the pasteboard (macOS has no "clipboard changed" notification) and records each new content once.

### init(store:pasteboard:)

Purpose: creates a monitor that records into `store`.
Input: `store`; `pasteboard` — `.general` in the app, a private pasteboard in tests.
Side effects:
- [pasteboard-read] remembers the current `changeCount`, so whatever is on the clipboard at launch is not recorded.

### start()

Purpose: starts polling.
Side effects:
- [schedule] a repeating timer every 0.5 s (0.25 s tolerance, so macOS can batch wakeups); it runs in all run loop modes, so it keeps working while menus are open.
Calls later:
- `check()` — on every tick.

### skipCurrentChange()

Purpose: tells the monitor that Pasty itself just wrote to the pasteboard, so the change is not recorded as a new copy.
Side effects:
- [pasteboard-read] remembers the current `changeCount`.
Invariants:
- INV-Capture-3: content written before `skipCurrentChange()` is not recorded by the next `check()`.

### check()

Purpose: records the pasteboard contents if they changed since the last check.
Side effects:
- [pasteboard-read] reads `changeCount`; if it changed, reads every type of every pasteboard item (types starting with `dyn.` are skipped), the file URLs and the plain string.
- [apps-read] asks which app is frontmost — it becomes the item's source app.
- [schedule] for a single copied video file, loads its thumbnail and duration in the background (see `record`).
Uses:
- `Prefs.paused` — when paused, the change is consumed but not recorded.
- `Prefs.ignoredApps` — content copied while one of these apps is frontmost is not recorded.
- `Prefs.saveImages` — see `record`.
- `HistoryStore.add(kind:text:hash:contents:appBundleID:thumbnail:filePath:)`
- `HistoryStore.hash(_:)`
- `HistoryStore.updateMedia(id:thumbnail:text:)`
- `MediaFile.kind(of:)`
- `MediaFile.imageInfo(data:)`
- `MediaFile.imageInfo(url:)`
- `MediaFile.videoInfo(url:)`
- `MediaFile.formatDuration(_:)`
Invariants:
- INV-Capture-1: content carrying a "don't save me" marker (`org.nspasteboard.ConcealedType`, `TransientType`, `AutoGeneratedType`, 1Password, KeeWeb and similar) is never recorded.
- INV-Capture-2: while paused nothing is recorded, and resuming does not record what was copied during the pause.
- INV-Capture-5: content larger than 50 MB in total is not recorded.

### record(contents:fileURLs:string:imageData:appBundleID:)

Purpose: decides what kind of item the content is and adds it to the history. Also used for screenshots picked up from disk.
Input: `contents` — raw data to store; `fileURLs` — copied files; `string` — plain text, if any; `imageData` — PNG/TIFF of the first pasteboard item, if any; `appBundleID` — source app.
Rules, first match wins:
1. Exactly one file, and it is an image or a video → an `image` / `video` item named after the file, with `filePath` set. Images get "name — W×H" and a thumbnail right away; videos get them in the background.
2. One or more other files → a `files` item whose text is the list of paths, one per line.
3. Non-blank text → a `text` item; only the first 2000 characters are kept for search, the full text stays in `contents`.
4. Image data, if "Save images" is on → an `image` item "Image W×H" with a thumbnail.
5. Anything else is ignored.
Side effects:
- [schedule] for a video, a background task reads its duration and a frame, then updates the item.
Uses:
- `Prefs.saveImages`
- `HistoryStore.add(kind:text:hash:contents:appBundleID:thumbnail:filePath:)`
- `HistoryStore.hash(_:)`
- `HistoryStore.updateMedia(id:thumbnail:text:)`
- `MediaFile.kind(of:)`
- `MediaFile.imageInfo(data:)`
- `MediaFile.imageInfo(url:)`
- `MediaFile.videoInfo(url:)`
- `MediaFile.formatDuration(_:)`
Invariants:
- INV-Capture-4: the item kind follows the rules above: one media file → image/video with `filePath`; several files → `files`; text → `text`; image data alone → `image`.
- INV-Capture-6: a text item keeps at most 2000 characters in `text`, while its stored contents keep the full text.
- INV-Capture-9: with "Save images" off, image data without text or files is not recorded.

## ScreenshotWatcher

Purpose: watches the screenshot folder and reports each new image (⇧⌘3, ⇧⌘4) or screen recording (⇧⌘5) once macOS has finished writing it.

The callback `onCapture(url)` is set by the App module.

### systemFolder: URL

Purpose: where macOS saves screenshots.
Output: the `location` from the `com.apple.screencapture` settings if it is an existing folder, else the Desktop.
Side effects:
- [defaults-read] reads `com.apple.screencapture` → `location`.
- [disk-read] checks that the folder exists.

### folder: URL

Purpose: the folder actually watched: the custom folder from Settings, or `systemFolder`.
Side effects:
- [defaults-read] reads `com.apple.screencapture` (when no custom folder is set).
- [disk-read] checks the system folder exists.
Uses:
- `Prefs.screenshotFolder`

### restart()

Purpose: (re)starts watching with the current settings. Called at launch and whenever the screenshot settings change.
Side effects:
- [folder-watch] stops the previous watch; starts watching `folder` for writes, renames and links — unless "Add new screenshots" is off.
- [defaults-read] reads the system screenshot location (via `folder`).
- [disk-read] lists the media files already in the folder; they will never be reported.
- [log] logs when the folder cannot be opened (then nothing is watched).
Uses:
- `Prefs.watchScreenshots`
- `Prefs.screenshotFolder`
- `MediaFile.kind(of:)`
Calls later:
- `scan()` — on every change in the folder.
Errors:
- [disk-read] an unreadable folder counts as empty.

### stop()

Purpose: stops watching and forgets files still waiting to settle.
Side effects:
- [folder-watch] cancels the watch (closes the folder handle).

### scan()

Purpose: finds media files that appeared since the last scan and queues them until they are fully written.
Side effects:
- [disk-read] lists the folder (hidden files skipped; only images and videos count).
- [schedule] starts a 0.7 s repeating timer if files are queued and it is not running.
Uses:
- `MediaFile.kind(of:)`
Calls later:
- `checkPending()` — every 0.7 s while files are queued.
Errors:
- [disk-read] an unreadable folder counts as empty.

### checkPending()

Purpose: reports queued files whose size stopped changing.
Side effects:
- [disk-read] reads the size of each queued file.
Calls `onCapture(url)` for each file whose size is above zero and the same as at the previous check; stops the timer when the queue is empty.
Invariants:
- INV-Capture-7: files already in the folder when watching starts are never reported; a new file is reported exactly once, only after two consecutive checks saw the same non-zero size.
Errors:
- [disk-read] a file that disappeared (deleted or renamed before it settled) is dropped silently.

## MediaFile

Purpose: helpers for image and video files — type detection, thumbnails (at most 320 px), dimensions and duration.

### kind(of:) -> Kind?

Purpose: `.image` or `.video` from the file extension (by its UTType), nil for anything else.
Side effects: none

### imageInfo(url:) -> ImageInfo?

Purpose: width, height and a PNG thumbnail of an image file.
Side effects:
- [disk-read] reads the image file.
Output: nil if the file is not a readable image.

### imageInfo(data:) -> ImageInfo?

Purpose: the same for image data in memory.
Side effects: none

### videoInfo(url:) async -> VideoInfo

Purpose: duration and a thumbnail (the frame at 1 s, or at half the length for shorter videos) of a video file.
Side effects:
- [disk-read] reads the video file.
Output: fields are nil when they cannot be read.

### videoSize(url:) async -> NSSize?

Purpose: a video's frame size in pixels as it is displayed (rotation applied), for sizing the preview window.
Side effects:
- [disk-read] reads the video file's track information.
Output: nil when the file has no readable video track.

### formatDuration(_:) -> String

Purpose: seconds as `m:ss`, or `h:mm:ss` from one hour.
Side effects: none
Invariants:
- INV-Capture-8: `formatDuration` rounds to whole seconds: 5 → `0:05`, 65.4 → `1:05`, 3725 → `1:02:05`.
